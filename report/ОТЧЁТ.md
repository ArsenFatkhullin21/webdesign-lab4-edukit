## 2. Описание дизайн-системы

**Название и бренд:** EduKit — дизайн-система образовательной платформы (онлайн-школа программирования; развитие сайта CodeLab из лаб. 1–3). **Характер:** спокойный, деловой, дружелюбный — синий акцент, скруглённые формы, плотная типографика Manrope + Inter.

**Принципы:**
1. **Ясность** — подписи всегда видимы, состояния различимы; компонент понятен без инструкции.
2. **Консистентность** — только токены, никаких «жёстких» цветов в компонентах (проверено поиском по CSS: ни одного hex-значения вне токенов, кроме `rgba` оверлея в токенах).
3. **Доступность** — WCAG 2.1 AA: контраст, видимый фокус, клавиатура (Tabs, Modal, Tooltip), `prefers-reduced-motion`. Проверено автоматически axe-core по всем stories в обеих темах (86 × 2 = 172 прогона, **0 нарушений**).
4. **Адаптивность** — Footer, Table, Form перестраиваются/прокручиваются на узких экранах.
5. **Расширяемость** — варианты добавляются BEM-модификаторами (`ds-btn--danger`), старый API не ломается (SemVer).

**Целевые продукты:** сайт школы (CodeLab), личный кабинет студента, админ-панель расписания.

## 3. Дизайн-токены

Формат — **W3C Design Tokens (DTCG)**: `$value` / `$type`, ссылки `{color.primitive.blue.600}`. Сборка — **Style Dictionary 5** ([style-dictionary.config.mjs](../style-dictionary.config.mjs)).

| Файл | Содержимое |
|---|---|
| [tokens/colors.json](../tokens/colors.json) | примитивы (blue, gray, green, amber, red) и семантика: background, text, border, action, feedback, focus |
| [tokens/typography.json](../tokens/typography.json) | семейства, 8 размеров, 5 начертаний, 3 межстрочных |
| [tokens/spacing.json](../tokens/spacing.json) | 10 ступеней, шаг 4 px |
| [tokens/radii.json](../tokens/radii.json), [shadows.json](../tokens/shadows.json), [motion.json](../tokens/motion.json) | радиусы; тени (DTCG-объекты); длительности и cubic-bezier |
| [tokens/themes/dark.json](../tokens/themes/dark.json) | тёмная тема: только переопределения семантики и теней |

Ключевая идея — семантические токены ссылаются на примитивные, поэтому в `tokens.css` они остаются `var(...)`:

```css
--color-semantic-action-primary: var(--color-primitive-blue-600);
--color-semantic-text-default:   var(--color-primitive-gray-900);
```

**Отступления от примера в методичке (обоснованы контрастом, как в лаб. 2):** `text.muted` = gray-600 `#5B6472` вместо gray-500 (на сером фоне 4.39 < 4.5); добавлены `action.link` (в тёмной теме blue-400, а кнопка остаётся blue-600 с белым текстом), `feedback.*`, `focus.ring`; shadow в DTCG — объект, а не строка. Спецификация DTCG требует `$value/$type`, поэтому вместо `value/type` из методички использован именно этот вид (Style Dictionary 5 читает его при `usesDtcg: true`).

Скриншоты: [Tokens → Colors (светлая)](screens/tokens-colors-light.png), [(тёмная)](screens/tokens-colors-dark.png), [Typography](screens/tokens-typography.png), [Spacing](screens/tokens-spacing.png). Страница Tokens в Storybook строится прямо из JSON-файлов, поэтому не может разойтись с кодом. Скриншоты самих JSON и `tokens.css` — откройте файлы по ссылкам выше (в отчёт вставьте скрин из редактора).

### Задание 3 — визуальная регрессия («отлично»)
1. **CI:** [.github/workflows/chromatic.yml](../.github/workflows/chromatic.yml) — на каждый `push` ставит зависимости, генерирует токены и запускает `npx chromatic` (с `fetch-depth: 0`, токен из `secrets.CHROMATIC_TOKEN`). **Реальный запуск не выполнялся** — нужны репозиторий и токен **[ЗАПОЛНИТЬ: скриншот diff из Chromatic]**.
2–3. **Эксперимент с diff — выполнен локально.** Чтобы не ждать облако, написан [tools/visual-regression.mjs](../tools/visual-regression.mjs): снимает все 86 stories × 2 темы (172 снимка), сравнивает с эталоном через pixelmatch и рисует diff. Изменение: в `colors.json` `blue.600` с `#2563EB` на `#DC2626`, пересборка. Результат: **изменились 79 из 172 снимков** — [эталон](screens/vr-baseline-button.png) → [после](screens/vr-current-button.png) → [diff](screens/vr-diff-button.png); также Header: [эталон](screens/vr-baseline-header.png), [после](screens/vr-current-header.png), [diff](screens/vr-diff-header.png). Затем изменение откатано — повторный прогон показал **0 различий**. Порог допуска 0.02% пикселей: без него два снимка давали 4–28 px шума субпиксельного сглаживания.
4. **Как это защищает от регрессий.** Одно изменение токена затрагивает десятки компонентов — вручную их не обойти. Тест показал, что правка одного цвета в JSON задела 79 состояний (кнопки, ссылки, Badge, Pagination, Tabs, Header, Form, Modal в обеих темах), и reviewer видит каждое место на diff-картинке до слияния. Chromatic делает то же в облаке + хранит эталоны, ведёт процесс принятия/отклонения изменений в Pull Request и снимает в нескольких браузерах.

## 9. Вывод

**Дизайн-система vs набор компонентов в проекте.** В лаб. 2 стили лежали внутри сайта и были привязаны к его страницам; здесь токены — единственный источник истины, компоненты не знают о страницах, у системы есть версии, changelog, документация и тесты. Её можно подключить в другой продукт, не копируя CSS. Подтверждение из работы: смена тёмной темы и смена цвета бренда делались правкой JSON, без изменения компонентов.

**Как Storybook помогает команде.** Каждый компонент и каждое состояние видно изолированно (в том числе «hover/focus», которые на сайте трудно воспроизвести), `argTypes` дают живую панель параметров и автоматическую таблицу API, a11y-аддон показывает нарушения, а stories служат основой для визуальных тестов — одни и те же примеры работают как документация, песочница и тест-кейсы.

**Самое сложное / неожиданное.** (1) Собрать тёмную тему как *отдельный набор токенов* в Style Dictionary: нужно, чтобы базовые токены участвовали в разрешении ссылок, но не попадали в выходной файл (`include` + фильтр `isSource`). (2) DTCG-формат не совпал с примером методички (`$value`, объектные тени). (3) Автоматическая проверка нашла проблему контраста, невидимую глазу. **[Добавьте свои впечатления.]**

## 10. Ответы на контрольные вопросы (кратко)

1. **Дизайн-система** — продукт: токены + компоненты + правила + документация + процессы; **UI Kit** — только набор визуальных элементов.
2. **Atomic Design** — atoms → molecules → organisms → templates → pages.
3. **W3C Design Tokens** — стандарт JSON-описания токенов (`$value`, `$type`, ссылки); инструменты (Style Dictionary, Figma) понимают один формат.
4. **Style Dictionary** — превращает токены в CSS/SCSS/JS/iOS/Android; решает проблему рассинхронизации платформ.
5. **Примитивный токен** — «сырое» значение (`blue-600`); **семантический** — роль (`action-primary`), ссылается на примитив; тема меняется подменой ссылок.
6. **Storybook** — среда разработки и документации компонентов в изоляции.
7. **Story** — конкретное состояние компонента; **Args** — его входные параметры, управляемые из панели Controls.
8. **Chromatic** — облако для Storybook: хостинг + визуальные тесты + ревью изменений.
9. **Визуальная регрессия** — сравнение скриншотов до/после, чтобы поймать непреднамеренные изменения внешнего вида.
10. **SemVer** — MAJOR.MINOR.PATCH: несовместимые изменения / новая функциональность / исправления.
